# M01 declared matrix optimizer variants

`muon_project_fp32` uses zero original-W M, `M=.95*M+G` and Nesterov input `G+.95*M`. Configuration can explicitly disable Nesterov for a separately recorded sensitivity; it never changes Muon+ momentum. `muon_plus_{none,row,col,row_col,col_row}_fp32` use zero original-W EMA `M=mu*M+(1-mu)*G`, default mu=.95, no Nesterov or bias correction. Normalization-off uses that identical EMA and the Muon+ multiplier. At each serial normalization stage the divisor is `sqrt(sum(O**2, axis)+1e-8)`, with epsilon inside sqrt. Row/column axes refer to original W orientation. Each composed stage uses the previous normalized output.

All variants use five literal Jordan iterations: `A=X@X.T; X=3.4445*X-4.775*(A@X)+2.0315*((A@A)@X)`, after Frobenius norm plus1e-7. Transpose iff original rows>columns (working rows≤columns), then restore. Muon scales by `sqrt(max(1,rows/cols))`; Muon+ scales by `sqrt(rows/cols)`. The polynomial is approximate, not an exact SVD polar factor. Product proposals require dense FP32 matrices; the public polynomial also accepts CPU float64 for independent fixtures. No BF16 conversion is hidden. Muon+ native EMA uses `mul_(mu).add_(G,alpha=1-mu)`; its native arithmetic order is declared for exact same-device fixtures.

A proposal owns detached original-W state/reference/displacement and never mutates W/gradient/old M. Decoupled decay acts on W before displacement. Commit copies the reference then adds displacement preserving Parameter identity. Matrix initial state is exactly `{momentum}` with W shape/dtype/device, with no fictitious Adam counter. Auxiliary state has CPU FP32 scalar step and device FP32 exp_avg/exp_avg_sq. No moment is stored in polar, normalized, rotated or storage coordinates.

`MatrixMethodAdapter` requires the exact explicit internal projection manifest plus auxiliary no-decay group. Embeddings, heads and norms use configured scalar AdamW (defaults independent LR=.001, betas=.9/.99, epsilon1e-8, decay0). Matrix LR comes from the schedule and has no implicit tie to auxiliary LR. `run --phase explore` accepts an explicit method object `{name,adaptation_label,config,learning_rate}` in its finite smoke/pilot-bootstrap envelope, records it in the immutable scientific configuration and run metadata, and checks that exact declaration on full-state resume. Names/normalization orders must match. Source, parity, operation and rights eligibility are separate. No protected/query outcome enters an optimizer.
