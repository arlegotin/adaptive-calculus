# Exact byte blocks and resumable logical batches

H03 supplies data correctness before model integration. Run the bounded fixture checks with `.venv/bin/python -m ralup test-harness --suite data`. A passing result applies to byte coverage, carry contexts, deterministic restoration, packing invariance and final denominators; it does not pass WP02, authorize protected test targets, or demonstrate neural training. `tile_article(Article)` returns one article's `TargetBlock` list. Each block declares an original half-open target interval of at most 128 bytes. At offset zero the sequence starts with input-only boundary token 256. Other blocks prepend up to 128 preceding bytes from that same article. Inputs are `sequence[:-1]`, labels are `sequence[1:]`; masks score the declared raw target bytes only, excluding context. Position IDs start at zero in each original sequence. There are 257 vocabulary symbols, and labels contain only raw bytes 0–255. There is no EOS target or cross-article concatenation.

`BatchCursor.from_articles(articles, seed=...)` is the explicit in-memory fixture interface, with `fixture:<ordinal>` document IDs. Its safe JSON state contains hex fixture content; use `from_manifest` for corpus streams. `BatchCursor.from_manifest(path, sha256, partition=..., seed=...)` authenticates the frozen manifest, H01 preparation/source references, pinned source assets and all derived files before indexes are used. It verifies accepted real H02 source/exclusion/partition hashes and compares selected document metadata with the authenticated H01 indexes. Run from the project root so historical relative source references retain their accepted interpretation. It does not repeat reconstruction or MinHash. Indexed IDs are `<source_sha256>:<split>:<article_ordinal>`; raw article SHA is dedup identity, not document identity. Original global source-row ranges and ordered source shards remain in document metadata. Content file identity/size/timestamps are checked around each selected read to detect changes after authentication.

Ordinary partition selectors are `meta-train`, `meta-development`, `target-training`, and `development`. The last selects official `validation` and preserves all 61 independently protected documents, including any duplicate content identities. The `test` selector fails before source access; E03 has not authorized test TARGET construction or scoring. Authentication and metadata comparison are non-scoring provenance operations and create no official test targets.

`next_logical_batch(cursor, target_budget=8192)` selects precisely the requested scored-byte budget, crossing epoch boundaries when necessary. An optional `run_target_budget` limits total selection and yields a final short batch, followed by an empty batch. These are data-selection limits supplied by callers; H03 assigns no scientific training budget. `LogicalBatch.target_count` is the selected-target denominator. Future H04 consumers must backpropagate summed NLL over physical microbatches, divide gradients once by this logical denominator, then clip once. `pack_microbatches(batch, sequences_per_microbatch)` groups original selected sequences without reselection. Tensor consumers may add padding with false masks; H03 adds no padded tensor representation.

Splitting a block changes only its score mask. The original `target_start`, `target_end`, inputs, labels and position IDs stay fixed across carries. `TargetBlock.scored_offsets()` returns the selected article byte offsets. The cursor stores the original block ordinal and unconsumed score interval, never a retiled continuation.

The corpus cursor holds per-document cumulative block counts and a shuffled uint32 block permutation. It reads at most the current block's 256-byte context/target slice, rather than creating millions of tensor sequences or copying corpus strings. Seeded `random.Random` is the named `data` stream. Physical packing fields never enter cursor selection or state. At an epoch boundary the completed permutation position remains at its end; the following selection increments the epoch and shuffles the same compact permutation using the saved data RNG.

`cursor.state` is owned JSON-compatible metadata with schema version, authenticated source/data/exclusion/partition hashes, little-endian uint32 permutation encoded in base64, epoch and permutation position, carried score interval, named RNG state, run limit and coverage counters. Restore with `BatchCursor(json.loads(json.dumps(saved_state)))`; no pickle or executable deserialization is used. Restoration authenticates sources again, checks permutation completeness/uniqueness, carry bounds and exact progress algebra. H07 will own checksummed atomic publication of full model/optimizer/cursor state; H03 does not claim full-state resume.

Every epoch is a permutation of disjoint document byte intervals. Therefore `unique_target_count = min(cumulative_target_count, total_target_bytes)` is exact from a fresh stream through any carry and any number of epochs. `repeated_target_count` is the remaining cumulative count. This needs no set containing hundreds of millions of offsets. Restoration checks cumulative progress against completed epochs, consumed permutation blocks and carry progress independently of these derived counters.
