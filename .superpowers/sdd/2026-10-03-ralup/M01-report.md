## Implementation and interfaces

Created `src/ralup/optim/muon.py`, `muon_plus.py`, and `matrix_adapter.py`. `orthogonalize_five_step` is the literal five-step Jordan polynomial, coefficients `(3.4445,-4.775,2.0315)`, Frobenius norm plus `1e-7`, transpose iff original rows>columns, then transpose back. Product arithmetic is FP32; CPU float64 is supported by the public primitive for independent fixtures. This is an approximate polar realization, not an exact SVD; upstream BF16 release reproduction is not claimed.

`MuonUpdateRule(config)` initializes original-W momentum to zero, updates `M=beta*M+G`, default beta=.95, uses Nesterov `G+beta*M` (or an explicitly configured no-Nesterov sensitivity), and scales by `sqrt(max(1,rows/cols))`. `MuonPlusUpdateRule(config)` uses original-W EMA `M=mu*M+(1-mu)*G`, default mu=.95, without Nesterov/bias correction; normalization names are none, row, col, row_col and col_row, and scaling is `sqrt(rows/cols)`. Each serial divisor is `sqrt(sum(O**2,axis)+1e-8)`, with epsilon inside sqrt and the next stage operating on the preceding output. Native EMA arithmetic uses `mul_(mu).add_(G,alpha=1-mu)`.

Proposals own detached reference/displacement/new moments and preserve W/gradient/old state. Decoupled decay acts on the original W reference before displacement. Commit preserves Parameter identity. Matrix optimizer state is exactly original-W `{momentum}`; auxiliaries retain separate original-W AdamW `{step,exp_avg,exp_avg_sq}`. No moment is stored in polar, normalized, rotated or quantized coordinates.

`MatrixMethodAdapter` uses the explicit internal projection manifest, with no embedding/head matrix-shape heuristic. Auxiliary embeddings/heads/norms use separately configured no-decay scalar AdamW; defaults are independent LR .001, betas .9/.99, eps1e-8. Matrix LR comes from the schedule. `optim/base.py` adds trusted parameter-rule/group-schedule hooks used by proposal collection, candidate validation and commit.

`baselines/registry.py` registers `muon_project_fp32` and all five `muon_plus_<order>_fp32` names, exact adaptation labels/configuration/departures/operation and rights inventories. `baselines/muon_checks.py` and `__main__.py` implement `verify-baselines --suite muon` and explicit matrix method selection in the finite explore envelope: `{name,adaptation_label,config,learning_rate}`.
