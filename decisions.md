# Engineering decisions

2026-10-03 — F01 implements the configuration and record boundary. These choices implement the approved specification; no methodological amendment or artifact invalidation is introduced.

- Place the importable package under project-root `src/ralup`, with setuptools packaging and a standard-library-only runtime. Python's minimum supported syntax is 3.11; the current focused checks run on Python 3.14.6 arm64. Numerical dependency versions and device tolerances remain evidence-dependent F02–F05 work.
- Encode canonical JSON with sorted string keys, UTF-8, compact separators, and nonfinite rejection. Do not coerce arbitrary Python keys, tuples, sets, or custom objects into JSON. Freeze resolved mappings and lists recursively; the hash covers exact canonical bytes. Never overwrite templates.
- Resolve evidence through matching nested fields, accepting replacements only for explicit null values. Preserve the required work-package gate records inside the hashed resolved payload. Use the common gate statuses `pass`, `blocked`, `negative`, and `inconclusive`; unsupported external spellings are rejected at this boundary. A pass requires hashed artifact provenance and no blockers. References establish syntax and provenance identity; artifact-consuming operations must verify file bytes.
- Make resolution purpose-specific. Hardware discovery (`doctor`) has no evidence prerequisite; data preparation requires WP00 and environment/lock records but no training budgets. Production training requires WP00/01/02/04 and its measured scientific inputs. Final meta resolution adds WP06 frozen controller/normalizer/sampling; confirmation adds WP07 and B*/seeds/n/analysis/manifest. This boundary does not implement bootstrap meta calibration or grant test access.
- Mark smoke data explicitly synthetic, use a 1-layer/8-wide/2-head fixture, and default to two finite steps. Enforce at most 16 fixture continuation steps, no warm start, and physical microbatch one. Its specified CPU/identity path is a fixture setting, not measured CPU or MPS numerical acceptance. Scientific purposes reject synthetic smoke.
- Retain S09's big-endian first-64-bit split interpretation and integer/rational threshold comparisons; template fractions document allocations and do not authorize floating-point splitting. Preserve exact GELU (`approximate="none"`) and LayerNorm epsilon `1e-5`. Keep only internal projections quantized, all other quantities FP32, moments in W coordinates, and tau-one assistance bypass.
- Preserve the original input/context/position IDs when splitting loss-mask intervals at logical-batch boundaries. Refresh realized/cached history at next-step preparation. These are recorded implementation obligations for later data/training tasks, not algorithms delivered by F01.
- Use non-executable tensor data plus JSON metadata for later checkpoints, with checksums and atomic publication. The exact tensor container remains for the environment/checkpoint tasks; F01 writes no executable checkpoint format.
- Publish immutable run metadata once using exclusive creation. Keep completion dispositions in a separate append-only `status.jsonl` referenced by `run.json`, and measurements in `metrics.jsonl`. Reopening must use existing metadata. Reject metadata tampering and incomplete ledger tails rather than repairing history silently. Each directory is owned by one writer; no multiprocess scheduling guarantee is implied.
- Count stream, unique, additional-loss, backward, and query targets independently. Keep forward-context work separate and retain null for unmeasured timings/memory/NLL/checkpoints/telemetry. Do not sum overlapping work or RSS/Metal counters. Per-matrix telemetry is a structured object, leaving its numerical collection to later tasks.
- Official validation is development. Confirmation config resolution is necessary but insufficient for test scoring: later code must verify the locked manifest and completed final checkpoint/status inventory for every planned arm before opening protected targets.

All scientific runtime gates remain open. No source revision, numerical release compatibility, MPS success, continuation horizon, confirmation sample size, or acceptance tolerance has been guessed for scientific execution.
